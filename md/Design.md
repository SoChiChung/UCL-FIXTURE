> **版本**：v1.0

> **目标读者**：前端工程师、UI/UX 设计师、后端数据工程师

## 0. 文档导读

本阶段交付一份可直接进入开发的产品设计文档，覆盖产品、交互、信息架构、视觉与数据结构五个维度。核心结论先行：

1. **产品形态**：单页可视化赛程对比工具，核心交互闭环为「搜索 → 多选 → 矩阵对比 → 冲突/队长路线识别」。
2. **最关键的视觉决策**：赛程矩阵采用 **图标（主场实心 / 客场描边）+ 对手三字缩写** 的格子格式，而非 `H vs NAP` / `A @ NAP` 文本，理由是扫读效率更高、矩阵更紧凑（详见 §12）。
3. **「冲突」的本质是「开球时间槽（Kickoff Slot）」**：欧冠每轮比赛高度集中在 2~3 个开球时间点，判断冲突、错开、队长切换，本质是对时间槽的聚类与对比，而非逐分钟比较。
4. **移动端不做横向矩阵**：降级为「按时间槽纵向排列的时间线卡片」，横向铺 10 队在小屏不可用（详见 §13）。

## 1. 产品目标

### 1.1 核心目标

让 Fantasy 玩家在 **3 秒内** 对所选球队完成四个判断：

- **哪天有比赛**（按日期/星期扫描）
- **谁和谁撞车**（同一时间槽的比赛）
- **谁先踢、谁后踢**（开球时间先后）
- **赛程错开的球队**（适合 Captain Switch 的候选）

### 1.2 可量化验收指标（Success Metrics）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 首次找到某队赛程的耗时 | ≤ 3 秒 | 从搜索到看清该队某轮比赛 |
| 完成一次「3 队赛程对比」操作次数 | ≤ 5 次交互 | 搜索、点选、展开轮次 |
| 队长路线识别 | 无需手动计算 | 通过颜色/角标直接读出可切换对 |
| 移动端可用性 | 不横向滚动即可读完单轮 | 时间线卡片方案 |

### 1.3 非目标（Non-Goals，第一阶段明确不做）

- 不涉及积分计算、球员数据、阵容优化（仅「球队 × 赛程」维度）。
- 不做赛程订阅/提醒推送。
- 不做账号体系、多设备同步。
- 不做后端：数据以静态 JSON 全量载入，前端本地计算与过滤。

## 2. 用户场景（Persona & Scenario）

### 2.1 目标用户

- **Persona A「赛程党队长」**：每周三前必须决定队长。核心诉求：找到「先踢的队当队长 → 踢完换到后踢的队」的路线。
- **Persona B「多队持有者」**：阵容里同时持有多队球员。核心诉求：看这几队赛程是否撞车、开球是否错开。
- **Persona C「选人犹豫党」**：赛前比较两支候选队未来几轮的对手与日期。核心诉求：快速横向扫读。

### 2.2 关键用户故事

| 编号 | 作为… | 我想… | 以便… |
| --- | --- | --- | --- |
| US-1 | 玩家 | 用 `ARS` 或 `Arsenal` 搜到球队 | 快速添加，无需记全名 |
| US-2 | 玩家 | 一次选中 3~5 支球队 | 横向对比它们的赛程 |
| US-3 | 玩家 | 展开某一比赛日看到所有选中队的格子 | 一眼看出谁在周二、谁在周三 |
| US-4 | 玩家 | 看清同一开球时间槽里的球队 | 判断哪些比赛撞车 |
| US-5 | 玩家 | 看清「先踢 / 后踢」顺序 | 规划队长切换路线 |
| US-6 | 玩家 | 悬停格子看到完整对阵与时间 | 补充格子里省略的细节 |

### 2.3 典型任务流（以队长规划为例）

1. 搜索并选中持有球员的 3 支球队（如 ARS、NAP、INT）。
2. 展开「Matchday 3」。
3. 观察到 ARS 与 NAP 都在「周二 18:45」槽，INT 在「周三 21:00」槽。
4. 结论：周二 18:45 用 ARS 球员做队长 → 赛后切到 INT 球员。

## 3. 信息架构（Information Architecture）

### 3.1 页面为单页结构，无多路由

```
紫葱酱 Fantasy 赛程规划器（单页应用）
│
├── Header（品牌 + 全局操作：队长路线开关 / 清空选择）
├── Search Area（搜索框 + 实时下拉建议）
├── Selected Teams Area（已选球队 Tag 列表）
├── Fixture Matrix Area（核心区）
│   └── Matchday Accordion × 8
│       └── Schedule Matrix（日期 × 球队 矩阵）
└── Footer（数据来源 / 免责声明）
```

### 3.2 层级关系

- **球队（Team）** 与 **比赛日（Matchday）** 是两个正交维度，构成矩阵的行列。
- **比赛（Match）** 是矩阵的单元格内容。
- **时间槽（Kickoff Slot）** 是跨比赛日派生的分组维度，用于冲突与队长路线识别。

## 4. 页面结构（Page Structure）

### 4.1 Header

- 左侧：品牌标识（🧅 图标 + 「紫葱酱 Fantasy 赛程规划器」标题）。
- 右侧全局操作：
  - **队长路线（Captain Route）**：布尔开关，开启后矩阵按时间槽高亮并标注先后顺序（详见 §14.5）。
  - **清空（Clear All）**：一键移除所有已选球队。

### 4.2 Search Area

- 单个搜索输入框，占位符示例：「搜索球队名或缩写，如 ARS / Arsenal」。
- 输入即触发实时下拉（防抖 150ms），下拉项格式：`队名全称 (缩写)`。
- 支持键盘上下键选择、回车确认、Esc 关闭。

### 4.3 Selected Teams Area

- 展示为可横向换行的 Tag 列表。
- 未选择任何球队时，显示「热门球队快捷推荐」chips（降低冷启动成本，见 §14.1）。

### 4.4 Fixture Matrix Area

- 8 个 Accordion，对应 Matchday 1~8。
- 默认仅展开「当前比赛日」（依据数据中最接近当前时间的轮次，见 §11）。
- 每个 Accordion 展开后渲染一张赛程矩阵。

### 4.5 Footer

- 数据来源说明、更新时间、非官方声明（供 Fantasy 参考）。

## 6. 视觉设计系统（Visual Design System）

### 6.1 设计理念

**「卡片化的轻量足球经理游戏」**。通过以下手段达成：

- **卡片化（Card-Based）**：所有信息单元（Tag、Accordion、单元格、时间槽）都是带圆角、带柔和阴影的卡片，拒绝裸表格线。
- **圆角与留白**：大圆角（8~16px）+ 充足间距，营造轻松友好而非密集数据感。
- **柔和阴影**：低透明度、多层的浅阴影，模拟「实体卡牌」浮起感。
- **图标语义优先**：主/客用「实心 vs 描边」图标区分，颜色与形状双重编码（避免色盲用户仅靠颜色）。
- **克制的强调色**：大面积使用白/浅蓝，仅在「选中 / 高亮 / 冲突」处用黄色强调，制造「足球场上的高亮标记」感。

### 6.2 视觉词汇（避免项）

❌ 避免：企业后台（表格线、表单按钮、密集列表）、数据驾驶舱（暗色+霓虹）、金融仪表盘（红绿涨跌、K 线）。
✅ 倾向：圆角卡片、柔和阴影、图标化单元格、暖色强调。

## 7. Color System（色彩系统）

### 7.1 基础色板

基于品牌色派生一套语义化色阶。主品牌色为 `#427AB5`（蓝），强调色为 `#F7DD7D`（黄）。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `primary` | `#427AB5` | 主按钮、链接、品牌、选中态描边、主场实心图标 |
| `primary-dark` | `#335F8F` | 主色 hover/active、选中态文字 |
| `primary-light` | `#E8F0F8` | 主色浅底、中性 hover 背景 |
| `secondary` | `#406AAF` | 渐变终点、次级按钮、徽章 |
| `accent` | `#F7DD7D` | **选中 / 高亮 / 队长路线标记**、活动指示 |
| `accent-light` | `#FFE8BE` | 强调浅底、hover 暖底、提示卡片背景 |
| `surface` | `#FFFFFF` | 卡片、面板主面 |
| `surface-alt` | `#F6F8FC` | 交替行、次级卡片面 |
| `background` | `#F2F5FA` | 页面背景（可做极浅蓝→奶油渐变） |
| `border` | `#E2E7F0` | 卡片描边、分隔线 |
| `border-strong` | `#C9D3E3` | 强调描边、输入框聚焦前 |
| `text-primary` | `#1A2433` | 主文字（深海军蓝） |
| `text-secondary` | `#5A6678` | 次级文字、说明 |
| `text-muted` | `#8A94A6` | 占位、弱化信息 |
| `text-on-primary` | `#FFFFFF` | 主色块上的文字 |
| `success` | `#3E9D6E` | 「可切换/错开」正向提示 |
| `warning` | `#E8A13D` | 「冲突」警示（与黄色 accent 区分） |
| `danger` | `#D9534F` | 删除、错误态 |
| `home-fill` | `#427AB5` | 主场实心图标 |
| `away-fill` | `transparent`（描边 `#427AB5`） | 客场描边图标 |

### 7.2 Hover / Selected 语义

| 状态 | 规则 |
| --- | --- |
| `hover`（中性） | 背景 `#E8F0F8`，边框加深至 `#C9D3E3` |
| `selected`（已选/高亮） | 背景 `#F7DD7D`，文字 `#335F8F`，边框 `#F7DD7D` |
| `selected-hover` | `#FFE8BE` 底，其余同 selected |

### 7.3 可访问性说明

- `#427AB5` 对白字对比度约 **4.6:1**，满足 WCAG AA（正文 ≥4.5:1）；`#335F8F` 对 `#F7DD7D` 对比度约 **4.9:1**，满足 AA。
- 主客区分必须「图标形状 + 颜色」双编码，避免仅靠颜色（色弱兼容）。
- 冲突、队长路线等语义不能仅用颜色表达，需同时给出角标/文字（见 §12.6）。
- 具体色值在实现阶段需用对比度工具复核（本文数值为近似估算）。

## 10. 卡片设计规范（Card Design Spec）

### 10.1 Team Tag（球队标签）

```
┌──────────────┐
│  ARS      ×  │   ← 圆角胶囊(radius-full)，背景 #F6F8FC，描边 #E2E7F0
└──────────────┘
```

- **结构**：左侧可加一个队色小圆点（若提供队徽则用队徽），中间为三字缩写（Caption 600 字重），右侧为删除 `×`。
- **默认态**：白/浅灰底 + 细描边，文字 `#1A2433`。
- **hover**：背景 `#E8F0F8`，`×` 变为 `#D9534F`。
- **选中/激活态**（如队长路线模式下被选为队长）：背景 `#F7DD7D`，文字 `#335F8F`。
- **删除交互**：点 `×` 移除，带 1px 微反馈；满 10 队时搜索下拉禁用并提示。

### 10.2 Matchday Accordion（比赛日手风琴）

```
折叠态（collapsed）：
┌──────────────────────────────────────┐
│ ▶  Matchday 1         09-08 ~ 09-09 │   ← 白底，左侧 chevron 右指
└──────────────────────────────────────┘

展开态（expanded）：
┌──────────────────────────────────────┐
│ ▼  Matchday 1         09-08 ~ 09-09 │   ← chevron 下指，卡片带 accent 描边/浅底
│  ┌───────────────────────────────┐  │
│  │   (Schedule Matrix 内容)      │  │
│  └───────────────────────────────┘  │
└──────────────────────────────────────┘
```

- **标题结构**：`chevron 图标` + `Matchday N`（H3 700 字重）+ 右侧该轮日期范围（Caption）。
- **折叠/展开区分**：chevron 方向（▶/▼）+ 展开态卡片左侧或顶部出现 `accent` 强调条（`#F7DD7D`）+ 浅色背景变化。
- **默认展开**：当前比赛日默认展开，其余折叠（当前轮判定见 §11.3）。

## 11. Accordion 设计规范（Accordion Spec）

### 11.1 行为

- 一次仅允许一个比赛日展开（独占式 Accordion），或允许多个同时展开（需权衡）。
  - **推荐：多展开**（多选对比场景用户常需同时看多轮）。
  - 但为避免 8 张矩阵全开造成长页面，默认只开当前轮。
- 展开/折叠动画时长 200ms，缓动 ease-out，仅对高度做过渡。

### 11.2 状态机

```
collapsed ──(点击标题)──▶ expanded
expanded  ──(点击标题)──▶ collapsed
```

### 11.3 当前比赛日判定

- 依据数据的 `deadline`/`DateTime` 与「今天」比较：取 `DateTime ≥ 今天` 的最小 Matchday，若无则取最后一轮。
- 实现阶段需明确时区基准（建议统一 UTC，展示时转本地时区）。

## 12. Fixture Matrix 设计规范（核心）

### 12.1 矩阵结构

- **行**：日期（含星期 + 开球时间槽）。同一比赛日内，日期可有多行（周二、周三），每天下按开球时间槽再细分。
- **列**：已选球队（≤10）。
- **单元格**：该队在该日期的比赛，或空白。

```
| 日期          | Arsenal | Man City | Barcelona | Bayern | PSG |
|---------------|---------|----------|-----------|--------|-----|
| 周二 18:45    | 🏠 NAP  |          | ✈️ INT    | 🏠 PSV |     |
| 周二 21:00    |         | ✈️ POR   |           |        | 🏠 LIV |
| 周三 18:45    |         |          |           |        |     |
```

### 12.2 比赛展示格式方案对比（关键决策）

对四种格式做客观对比：

| 方案 | 示例 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 文本缩写 | `H vs NAP` / `A @ NAP` | 语义最完整 | 冗余（`vs`/`@` 已被主客语义覆盖）、占宽、扫读慢 | 不推荐 |
| B. Emoji + 缩写 | `🏠 NAP` / `✈️ INT` | 极紧凑、一眼分辨主客 | emoji 跨平台渲染不一致、无障碍差 | 可作为降级 |
| C. 自绘 SVG 图标 + 缩写 | `[H] NAP` / `[A] INT` | 紧凑 + 视觉完全可控 | 需自绘图标 | **推荐主方案** |
| D. 纯缩写 + 颜色 | `NAP`（蓝底=主/白底=客） | 最紧凑 | 仅靠颜色，色弱不可用 | 不可单独使用 |

**推荐方案（C，并以 B 为语义参考）**：

- 单元格 = **图标 + 对手三字缩写**。图标采用统一自绘 SVG：**主场 = 实心填充，客场 = 描边空心**，颜色用 `#427AB5`。
- 不出现 `vs` / `@` / `H` / `A` 等冗余文字（主客已由图标编码）。
- 通过 `title` / `aria-label` 补充完整文本（如 `Arsenal vs Napoli, Matchday 3, 2026-10-21, 21:00, Home`），保证无障碍与 Hover 兜底。

> **为何不用 emoji 作主方案**：🏠/✈️ 在不同系统渲染观感差异大，且无法保证所有场景可用；但可作为「图标库未就绪时」的临时降级。

### 12.3 Fixture Cell（比赛格子）

```
主场：┌───────────┐    客场：┌───────────┐
      │ ▉ NAP     │          │ ▢ INT     │
      └───────────┘          └───────────┘
      （实心图标）            （空心图标）
```

- 尺寸：最小高度 40px，内边距 8px，圆角 `radius-sm`。
- 主/客视觉编码：
  - 主场：实心圆点/旗帜图标 + `primary` 底纹或深色文字。
  - 客场：空心圆点 + 白色底 + `primary` 描边。
- 无比赛：**留白**（空白单元格，不显示 `N/A`、`-`、`No Match` 等占位，仅保留极浅背景区分）。

### 12.4 Hover 信息（Tooltip）

悬停格子显示浮层（延迟 200ms 出现，避免误触）：

```
┌─────────────────────────┐
│  Arsenal vs Napoli       │   ← 主队视角：主队在前
│  Matchday 3              │
│  2026-10-21              │
│  21:00                   │
│  Home                    │
└─────────────────────────┘
```

- 客场球队的格子，视角切换为 `Napoli vs Arsenal ... Away`（保持「该队视角」）。
- 浮层内容字段：完整对阵、Matchday、日期、时间、主/客身份。

### 12.5 冲突识别（撞车）

- **时间槽（Kickoff Slot）**：将同一比赛日的所有开球时间聚成槽位（欧冠通常 2~3 个，如 18:45 / 21:00）。
- 同一槽位内的单元格共享一种「槽位色描边」或槽位角标，让用户一眼看出「谁和谁同槽 = 撞车」。
- 冲突强调：当多支已选球队出现在同一槽位时，这些格子额外加 `warning` 色角标。

### 12.6 队长路线（Captain Route）

- 开启「队长路线」模式后，矩阵按开球时间**先后**对日期行排序，并在槽位标签上标注顺序（如 `① 18:45`、`② 21:00`）。
- 「可切换对」= 同一比赛日内，一个队在某槽、另一队在更晚槽 → 两者格子之间可用虚线连接或用 `success` 高亮。
- 队长路线模式下，颜色/顺序不能作为唯一信号，需配合序号角标文字。

## 13. Responsive Design（响应式设计）

### 13.1 断点

| 断点 | 范围 | 形态 |
| --- | --- | --- |
| Desktop | ≥ 1024px | 完整横向矩阵（主场景） |
| Tablet | 768–1023px | 横向滚动矩阵 + 冻结首列 |
| Mobile | < 768px | **竖向时间线卡片** |

### 13.2 Desktop（主场景）

- 全宽矩阵，列数随已选球队（≤10）横向铺开。
- **冻结（sticky）表头**与**冻结首列（日期列）**，横向滚动时球队名与日期始终可见。

### 13.3 Tablet

- 矩阵保留横向结构，容器内横向滚动；冻结日期列。
- 搜索区与已选 Tag 区可精简为单行。

### 13.4 Mobile（关键分析）

**横向矩阵在 <768px 不可用**（10 队 × 多日期 = 必须横滚，扫读体验差）。改用**竖向时间线**：

- 每个比赛日 Accordion 展开后，内容改为「按开球时间槽纵向分组」的卡片流：
  - 槽位标题：`周二 · 18:45`
  - 槽位内每张卡片：`[ARS] 🏠 NAP`、`[BAR] ✈️ INT`。
- 未选中的球队不占位（移动端只显示有比赛的球队，避免空白列浪费）。
- 队长路线模式：在槽位标题上标序号（`① 18:45`、`② 21:00`），垂直读即可判断先后。

## 14. UX Flow（用户体验流程）

### 14.1 首次进入（Zero State）

用户第一眼看到：

1. 品牌标题 + 一句价值主张（如「3 秒看清谁先踢、谁后踢、谁撞车」）。
2. 搜索框居中放大，提示「搜索球队名或缩写」。
3. 一组「热门球队」快捷 chips（预置高关注球队，如 ARS/MCI/BAR/BAY/PSG），点击即选中，降低冷启动成本。

> 冷启动策略：首屏不展示空矩阵，而是给出可立即点击的快捷入口，让用户在 1 次点击内产生第一条数据。

### 14.2 选择球队

1. 点击搜索框 → 输入 → 150ms 防抖后显示下拉建议（`队名 (缩写)`）。
2. 键盘/鼠标选择 → 添加到已选 Tag 区。
3. 重复直到选满所需球队（上限 10，满员提示）。
4. 点 Tag 的 `×` 或「清空」移除。

### 14.3 理解矩阵

- 图例（Legend）常驻，解释「实心 = 主场」「空心 = 客场」「同槽颜色 = 撞车」。
- 默认展开当前轮，用户看到的第一张矩阵就是「最近的比赛」。
- 列头球队名、行头日期都固定可读，格子内容只有图标 + 缩写，减少认知负担。

### 14.4 发现冲突

- 同一时间槽的格子共享描边色 → 用户扫一眼颜色就知道「谁和谁撞车」。
- 开启队长路线模式后，撞车格额外加 `warning` 角标。

### 14.5 发现队长路线

1. 用户开启「队长路线」开关。
2. 日期行按开球时间排序，槽位带序号（①②③）。
3. 「先踢的队（序号小）」与「后踢的队（序号大）」形成可切换对，格子之间用连接线或 `success` 高亮。
4. 用户据此规划：早槽队做队长 → 赛后切到晚槽队。

## 15. 数据结构设计（Data Structures）

> 说明：本节用「字段表 + 最小 JSON 示例」描述结构（数据描述，非代码）。字段命名与真实数据源做了映射（见 §15.5）。

### 15.1 Team（球队）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 内部唯一标识（可取自数据源 `htId`/`atId`，或直接用 code） |
| `code` | string | 三字缩写，如 `ARS`（真实数据源为 `htCCode`/`atCCode`） |
| `name` | string | 全称，如 `Arsenal` |
| `pot` | string | 抽签档次（可选，如 `Pot 1`） |
| `crest` | string | 队徽图片 URL（可选） |

### 15.2 Match（比赛）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 比赛唯一 ID |
| `matchday` | number | 1~8 |
| `dateTime` | string(ISO 8601) | 开球时间，如 `2026-09-09T18:45:00Z` |
| `kickoffSlot` | string | 派生的开球槽标签（如 `18:45`） |
| `home` | TeamRef | 主队引用 |
| `away` | TeamRef | 客队引用 |

`TeamRef = { id, code, name }`（冗余存储缩写与全称，避免渲染时跨表查找）。

### 15.3 Matchday（比赛日）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `number` | number | 1~8 |
| `dateRange` | { start, end } | 该轮最早/最晚开球日期 |
| `matches` | Match[] | 该轮全部比赛 |
| `slots` | string[] | 派生的开球时间槽列表（去重、升序） |

### 15.4 FixtureMatrix（赛程矩阵 / 前端派生结构）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `teams` | Team[] | 已选球队（≤10） |
| `matchdays` | Matchday[] | 1~8 轮 |
| `cells` | Map\<key, Match\|null\> | 键为 `(matchday, teamId, slotKey)`；无比赛为 null |
| `slotsByMatchday` | Map\<matchday, string[]\> | 每轮时间槽（用于冲突/队长路线） |

### 15.5 数据源归一化映射（关键工程提示）

真实数据文件 `fixtures_90_en.json` 与需求描述的简化 schema **不一致**，需在接入时做归一化：

| 需求字段 | 真实数据字段 | 备注 |
| --- | --- | --- |
| `HomeHTName` | `htName` | 主队全称 |
| `HTShortName` | `htCCode` | ⚠️ 真实 `htShortName` 是「全称变体」，真正的 3 字母码在 `htCCode` |
| `AwayHTName` | `atName` | 客队全称 |
| `ATShortName` | `atCCode` | 同上 |
| `DateTime` | `dateTime` | 格式为 `MM/DD/YYYY HH:mm:ss`，需解析为 ISO 8601 + 统一 UTC |
| `Matchday` | `gamedayNew` | ⚠️ `gameday` 字段不可靠（大量为 0），真实轮次在 `gamedayNew`（1~8） |

- 真实数据规模：**36 支球队**、**8 轮**、每轮 **18 场**（总计 144 场）。
- 数据为嵌套结构 `data.value[]`（每元素一个轮次），内嵌 `match[]`。
- 建议在前端做一次性解析归一化为上述扁平结构，并缓存派生结果（时间槽、日期范围）。

## 17. 后续开发建议（Roadmap）

### 17.1 实现优先级（第一阶段）

1. **数据归一化层**：解析 `fixtures_90_en.json` → 扁平 `Team/Match/Matchday` 结构（§15.5 映射需最先验证）。
2. **球队搜索 + 多选 Tag**：模糊搜索、实时下拉、10 队上限。
3. **赛程矩阵渲染**：Accordion + 矩阵 + 单元格（含主客图标）。
4. **冲突/时间槽聚类**：派生 kickoffSlot，槽位着色。
5. **队长路线模式**：时间槽排序 + 序号 + 可切换对高亮。
6. **响应式 + 移动端时间线**。
7. **空状态 + 热门球队推荐 + 图例**。

### 17.2 关键技术注意点

- **时区**：数据为特定时区，展示需统一 UTC → 本地时区转换，否则开球时间/星期会错位。
- **派生计算**：时间槽聚类、日期范围、当前轮判定均在前端一次性计算并缓存。
- **性能**：数据量小（144 场），无需后端，全量载入即可；但需避免在 10 队 × 8 轮渲染时做多余重排。
- **无障碍**：主客区分「形状 + 颜色」双编码；所有语义（冲突/路线）配文字角标。
- **图标方案**：优先自绘 SVG 主客图标；emoji 仅作临时降级。

### 17.3 后续可扩展（非第一阶段）

- 积分/球员维度对比（引入 Fantasy 积分系统）。
- 赛程订阅与开赛提醒。
- 拖拽排序球队、自定义时间槽高亮规则。
- 双语（中英）切换。
